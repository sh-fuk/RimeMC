# RimeMC

低スペックでも速く、マルチコア・GPU を使い切ることを目標にした、**Rust によるフルスクラッチ**の Minecraft サーバーです（既存サーバーの改造ではありません。AirWorld の設計のみ Linear 形式を参考にしています）。

- **言語: Rust** — GC が無いので GC 停止によるラグスパイクが起きない。ネイティブ速度。データ競合をコンパイル時に排除できるので、全コアを安全に並列利用できる。メモリ安全なのでバッファオーバーフロー系の脆弱性が構造的に起きない。
- **全コア活用** — Tick はセル（リージョン）単位でロックなしの並列処理、保存・変換・ワールド生成も全コアで並列。
- **GPU** — ワールド生成の地形計算を GPU（Metal / Vulkan / DX12）で実行。`gpu.enabled = true` がデフォルトで、GPU が無ければ自動で CPU にフォールバック。整数演算のみなので **GPU と CPU の結果はビット単位で一致**（テスト済み）。

## ビルド・起動

```bash
cargo build --release
```

```bash
./target/release/rime
```

初回起動時に `rime.toml` が生成されます。全機能はここでオン/オフ・調整できます。

| コマンド | 内容 |
|---|---|
| `./rime` | サーバー起動 |
| `./rime sync` | RAM ワールドを今すぐディスクに保存（OP のみ。下記参照） |
| `./rime status` | 状態表示（MSPT、RAM 使用量、GPU など） |
| `./rime stop` | 安全に停止（保存してから終了） |
| `./rime gen-secret` | RimeFleet 用のランダムなシークレットを生成 |
| `airworld-convert to-air <vanilla_world> <out>` | 通常ワールド → AirWorld |
| `airworld-convert to-mca <air_world> <out>` | AirWorld → 通常ワールド |
| `airworld-convert inspect <file.air>` | .air ファイルの中身・圧縮率を表示 |

`./rime sync` は `127.0.0.1` 限定の制御ソケットに、パーミッション `0600` のトークンファイル（`.rime-control`）で認証して接続します。そのため、サーバーディレクトリにアクセスできる管理者（OP）しか実行できません。サーバーコンソールでは `rime sync`、`op <name>`、`deop <name>` が使えます（OP 権限チェックあり）。

### AirWorld（`.air`）

Linear 形式（xymb-endcrystalme/LinearRegionFileFormatTools）を参考に、弱点を改善しました。

| Linear の問題 | AirWorld |
|---|---|
| リージョン全体が 1 本の zstd ストリームで、1 チャンク読むのに 1024 チャンク全部を展開 | チャンクごとに独立した zstd フレーム。1 チャンクだけ読める |
| 1 バイト壊れるとリージョン全体が読めない | チャンクごとの xxh3 チェックサムで、破損はそのチャンクだけに留まる |
| ヘッダの整合性チェックが無い | ヘッダ＋インデックスもチェックサム |
| 途中で切れたファイルを検出しにくい | フッタに総サイズ＋マジック |
| 信頼できないサイズ値による展開爆弾 | 全長さに上限、ちょうどのサイズで展開 |

- 中身はバニラが圧縮する前の**生 NBT そのもの**なので、`.mca` ⇄ `.air` の変換は NBT 単位で無損失（タイムスタンプ、1 MiB 超の `.mcc` 外部チャンクも含む）。変換ツールは書き込み後に読み戻して検証する。
- 書き込みは「一時ファイル → fsync → rename」のアトミック方式で、クラッシュしても新旧どちらかの完全なファイルが必ず残る。
- 実測（このリポジトリの E2E テスト）: 同じワールドで `.mca` 0.7 MiB → `.air` 0.3 MiB（生 NBT 比 12.7 倍圧縮）。
- RimeFleet 使用時は AirWorld 必須（設定検証で強制）。

### RimeFleet

```
プレイヤー ──► RimeRouter ──┬──► RimeNode 1
 (Java/統合版)              └──► RimeNode 2
```

- クライアントは常に Router とだけ通信する。ノード間の移動はサーバー内部のハンドオフなので、再接続もロード画面も発生しない設計。
- ワールドデータは Router が一括で保持する。ノードは、自分が担当するセルのチャンク以外は書き込めない（Router 側で強制）。
- **負荷分散**: 重み付き Rendezvous ハッシュで初期配置。最も重いノードが平均の `1 + imbalance_threshold` 倍を超えたら、セルを軽いノードへ自動移動する（隣接セル優先、移動クールダウンで行ったり来たりを防止）。
- **レッドストーン**: レッドストーンが動いているセルは 1 台のレッドストーン担当ノードに固定し、処理順序を決定的に保つ。
- **フェイルオーバー**: ハートビートが途絶えたノードの全セル（レッドストーン担当の役割も含む）を生存ノードに即座に再配置する。Node1 が落ちれば Node2 がすべてを担当する。
- **通信の安全性**: シークレット（32 文字以上、`rime gen-secret` で生成）から HKDF-SHA256 で鍵を導出し、HMAC による相互認証、ChaCha20-Poly1305 で暗号化と改ざん検知。暗黙のシーケンス番号で、リプレイ・順序入れ替え・反射攻撃を拒否する（テスト済み）。

### チート対策

- 判定ごとに違反レベル（VL）が時間で減衰するため、一瞬のラグでは処罰されない。デフォルトの処罰は **setback**（不正な移動・攻撃を巻き戻す）で、正規プレイヤーを誤って BAN することはない。高 VL でキック、BAN はデフォルトでオフ。すべて `[anticheat]` で設定できる。
- **誤検知対策**: Fly 判定は「物理的にあり得ない上昇・ホバリング」だけを検出し、落下は一切検出しない。そのため、エリトラ滑空中・滑空終了後の落下・浮遊・低速落下・激流・液体・はしご・クモの巣・乗り物・ノックバック・爆発・テレポート後は誤検知しない（テストで確認済み）。
- **NoFall** は検出に加え、落下ダメージをサーバー側で計算して必ず適用するので、チートそのものが無効になる。
- **X-ray** は、どこにも露出していない鉱石を石・深層岩に置き換えて送信する（チャンク境界も考慮）。`obfuscate` モードでは偽の鉱石も混ぜる。採掘統計による検出は通知のみ。

### スキン（Geyser 系のスキン不具合の修正）

- 旧形式 64×32 の Java スキンを、統合版向けに Java クライアントと同じ方法で 64×64 に変換（左腕・左脚が崩れる問題）。
- 統合版の HD スキン（128×128）を 64×64 に縮小。半透明のベースレイヤーが Java で黒くなる問題を修正。スリム腕モデルを正しく引き継ぐ。不正なスキンデータは拒否。

## 構成

```
crates/
  airworld/     AirWorld 形式・.mca 読み書き・airworld-convert
  rime-fleet/   暗号チャネル・負荷分散/フェイルオーバー・メッセージ定義
  rime-server/  サーバー本体（bin: rime）
    config.rs       rime.toml
    world/          チャンク・地形生成(CPU/GPU)・事前生成・RAM ワールド
    tick/           並列スケジューラ・Level Tick・Player Cost
    anticheat/      移動・戦闘・X-ray
    net/            Java プロトコル・統合版(RakNet)・スキン
    fleet_net.rs    Router / Node 実行部
    control.rs      ./rime sync 用の制御ソケット
```
